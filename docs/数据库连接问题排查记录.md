# 数据库连接与地图点亮问题排查记录

## 问题一：API 接口返回 Internal Server Error

**时间：2026-07-07 17:00 ~ 17:20**

### 问题现象

访问 API 接口 `http://47.99.33.44:8080/api/footprints` 返回 `Internal Server Error`。

### 排查过程

#### 第一步：查看后端日志

后端日志报错：

```
pymysql.err.OperationalError: (2003, "Can't connect to MySQL server on '127.0.0.1' ([Errno 111] Connection refused)")
```

**原因**：后端代码 `main.py` 中数据库 host 配置为 `127.0.0.1`，而后端运行在 Docker 容器中，容器内的 `127.0.0.1` 指向**容器自身**，不是宿主机上的 MySQL，所以连不上。

**解决**：将 host 改为 MySQL 容器的实际 IP 地址 `172.18.0.3`。

```python
DB_CONFIG = {
    "host": "172.18.0.3",   # 改为 MySQL 容器的 IP
    "port": 3306,
    "user": "xiaoxiaoyu123",
    "password": "h8ezXeZyhPpiRKXY",
    "database": "xiaoxiaoyu123",
}
```

#### 第二步：认证方式错误

修改 host 后重启容器，日志报错变为：

```
RuntimeError: 'cryptography' package is required for sha256_password or caching_sha2_password auth methods
```

**原因**：MySQL 8.0 默认使用 `caching_sha2_password` 加密方式，Python 连接时需要 `cryptography` 包支持。

**解决方法有两种：**

##### 方案 A：在后端容器中安装 cryptography 包（推荐，最终采用）

```bash
pip install cryptography
```

安装完成后重启后端容器即可。

##### 方案 B：修改 MySQL 用户加密方式为旧版

在 MySQL 中执行：

```sql
ALTER USER 'xiaoxiaoyu123'@'%' IDENTIFIED WITH mysql_native_password BY 'h8ezXeZyhPpiRKXY';
FLUSH PRIVILEGES;
```

### 最终结果

方案 A 执行后，重启后端容器，`/api/footprints` 正常返回：

```json
{"status": "success", "data": []}
```

## 问题二：地图页面白屏

**时间：2026-07-07 17:55 ~ 18:05**

### 问题现象

进入兴趣页后页面白屏，F12 控制台报错：

```
Uncaught TypeError: mapData.some is not a function
```

### 排查过程

查看 `fetchFootprints` 函数代码，发现前端将 API 返回的整个响应对象直接赋值给了 `mapData`。

**错误代码：**

```js
const data = await res.json();
setMapData(data);  // data 是 {status: "success", data: [...]} 对象
```

但 API 返回的格式是 `{status: "success", data: [...]}`，`mapData` 期望的是一个数组，却拿到了对象，导致后续调用 `mapData.some()` 时报错。

**修复代码：**

```js
const result = await res.json();
const footprints = Array.isArray(result.data) ? result.data : [];
setMapData(footprints);
```

## 问题三：点亮星星失败（500 Internal Server Error）

**时间：2026-07-07 17:30 ~ 18:25**

### 问题现象

点击定位传送后，提示"点亮失败，请检查网络或服务端状态"。控制台显示 `/api/checkin` 返回 500。

### 排查过程

查看后端日志：

```
[数据库错误] checkin: (1146, "Table 'xiaoxiaoyu123.footprints' doesn't exist")
```

**原因**：数据库 `xiaoxiaoyu123` 已创建，但其中的 `footprints` 表不存在。后端的 `init_db()` 建表函数只会在 `python main.py` 直接运行时执行，而 Docker 容器使用的是 `uvicorn main:app` 启动，不会触发 `init_db()`。

**修复**：添加 FastAPI lifespan 启动事件，确保容器启动时自动建表。

```python
from contextlib import asynccontextmanager

@asynccontextmanager
async def lifespan(app):
    """应用启动时自动建表"""
    init_db()
    yield

app = FastAPI(title="xiaoxiaoyu123 API", version="1.0.0", lifespan=lifespan)
```

将修改后的 `main.py` 上传到服务器后端容器并重启后，自动创建了 `footprints`、`messages`、`comments` 三张表。

## 问题四：记忆树页面白屏（3D 场景崩溃）

**时间：2026-07-07 19:00 ~ 19:30**

### 问题现象

进入"我的记忆树"页面白屏，控制台报错：

```
Uncaught Error: Could not load /51d48ec2845fbfb781f43ff09c2ccc26.jpg: undefined
An error occurred in the <CanvasImpl> component.
THREE.WebGLRenderer: Context Lost.
```

### 原因

`src/config/photos.js` 中配置了大量图片路径，但对应的图片文件不存在于 `public/` 目录中。Three.js 的 `useTexture` hook 在加载失败时抛出未捕获错误，导致整个 Canvas（WebGL 渲染器）崩溃，页面白屏。

### 解决过程

#### 第一步：移除已删除图片的记录（19:00）

在 `src/config/photos.js` 中删除已不存在的图片条目：

```js
// 删除
{ id: 10, url: '/51d48ec2845fbfb781f43ff09c2ccc26.jpg', ... }
```

#### 第二步：添加 Canvas 错误边界（19:05）

为防止单张图片加载失败导致整个页面崩溃，在 `MemoryArchive.jsx` 中添加错误边界组件：

```jsx
class CanvasErrorBoundary extends React.Component {
  constructor(props) {
    super(props);
    this.state = { hasError: false };
  }
  static getDerivedStateFromError() {
    return { hasError: true };
  }
  render() {
    if (this.state.hasError) {
      return <div>✨ 记忆星海正在加载中...</div>;
    }
    return this.props.children;
  }
}
```

用 `<CanvasErrorBoundary>` 包裹 `<Canvas>` 组件。

#### 第三步：替换 useTexture 为安全加载组件（19:15）

`useTexture`（来自 `@react-three/drei`）在图片加载失败时直接抛错，无法用 try-catch 捕获。改为自定义 `SafeTexture` 组件，使用 `THREE.TextureLoader` 手动加载并处理错误：

```jsx
function SafeTexture({ url }) {
  const [texture, setTexture] = useState(null);
  useEffect(() => {
    const loader = new THREE.TextureLoader();
    loader.load(url, (tex) => setTexture(tex), undefined, () => {
      // 加载失败：用 1x1 像素默认纹理替代，防止崩溃
      const fallback = new THREE.DataTexture(new Uint8Array([40, 40, 60, 255]), 1, 1);
      fallback.needsUpdate = true;
      setTexture(fallback);
    });
  }, [url]);
  return texture ? <meshBasicMaterial map={texture} transparent opacity={1} /> : null;
}
```

同时创建 `VideoTextureMesh` 组件安全加载视频纹理，失败时返回 `null`。

#### 第四步：移除未使用的 `useTexture` 导入（19:20）

```js
// 移除
import { ..., useTexture, ... } from '@react-three/drei';
// 保留
import { ..., useVideoTexture, ... } from '@react-three/drei';
```

### 最终结果

- 缺失图片显示为深色方块，不再导致 3D 场景崩溃
- 错误边界作为兜底，防止意外崩溃导致白屏
- 页面正常显示 3D 动态星海粒子效果

## 问题五：评论发送失败（422 Unprocessable Entity）

**时间：2026-07-07 19:35 ~ 19:40**

### 问题现象

在记忆树页面点击图片/视频后，发送评论，提示 `undefined`。控制台显示：

```
POST http://localhost:5175/api/comments 422 (Unprocessable Entity)
```

### 原因

前端发送评论请求时，未上传文件的情况下 `media_url` 和 `media_type` 变量值为 `null`（JavaScript），JSON 序列化后变成 `null`。而后端 Pydantic 模型期望 `str` 类型：

```python
class CommentCreate(BaseModel):
    ...
    media_url: str = ""
    media_type: str = ""
```

`null` 不是合法的 `str`，导致 FastAPI 请求体验证失败，返回 422。

### 解决

确保 `media_url` 和 `media_type` 为空时发送空字符串而非 `null`：

```js
// 修改前
body: JSON.stringify({
    media_url,    // null
    media_type,   // null
})

// 修改后
body: JSON.stringify({
    media_url: media_url || '',
    media_type: media_type || '',
})
```

## 问题六：教育背景页面空白（视频卡死）

**时间：2026-07-07 19:45 ~ 19:50**

### 问题现象

点击进入教育背景页面，只能看到音乐播放器，其他内容一片空白。

### 原因

`SchoolArchive.jsx` 中配置了视频映射 `"桂林电子科技大学": "/jsdx.mp4"`，但视频文件 `/jsdx.mp4` 不存在。代码检测到 `videoSrc` 有值（键匹配成功），判定需要播放视频，将 `showContent` 设为 `false`。然而视频文件不存在导致加载失败，`onEnded` 事件永远不触发，`videoFinished` 始终为 `false`，页面内容一直被视频遮罩层挡住，显示为空白。

### 解决

为 `<video>` 元素添加 `onError` 事件处理，视频加载失败时直接跳过，显示内容：

```jsx
<video
  autoPlay
  muted
  playsInline
  onEnded={() => setVideoFinished(true)}
  onError={() => setVideoFinished(true)}   // ← 新增：加载失败也跳过
>
  <source src={videoSrc} type="video/mp4" />
</video>
```

## 经验总结

| 问题 | 原因 | 解决方式 |
|------|------|---------|
| `Connection refused` | Docker 容器内 `127.0.0.1` 连不上 MySQL | host 改为 MySQL 容器 IP `172.18.0.3` |
| `cryptography package is required` | MySQL 8.0 加密方式需要加密包 | `pip install cryptography` |
| `mapData.some is not a function` | 前端未正确解析 API 嵌套响应 | 提取 `result.data` 再赋值 |
| `Table 'footprints' doesn't exist` | `uvicorn` 启动不触发建表 | 添加 `lifespan` 事件自动建表 |
| 3D 场景崩溃白屏 | `useTexture` 加载缺失图片抛未捕获错误 | `SafeTexture` 组件 + `CanvasErrorBoundary` 错误边界 |
| 评论发送 422 | `media_url` / `media_type` 为 `null` 不符合 `str` 类型 | 改为 `media_url: media_url \|\| ''` |
| 教育背景页空白 | 视频文件不存在导致 `onEnded` 不触发 | 添加 `onError` 事件跳过加载失败的视频 |
